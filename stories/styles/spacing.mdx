# Spacing

Space is the distance between objects in your design. It should be used to
complement the purpose of a page by creating hierarchy and helping the content
become more useful and understandable.

## 1. Spacing units

Spacing is determined by the font-size base set on the document's body tag and
scaled via `rem` units. We have determined that the industry-standard `16px`
value is ideal for our base due to the ease of its role in multiplication and
division.

These are the standardized units used across token and utility naming:

We utilize t-shirt sizing for our base spacing units. This provides us with an
easy-to-understand naming system for a limited palette of popular sizes. Nathan
Curtis summarizes this approach in his article entitled [Space in Design
Systems][1].

If your design requires a different amount of space than listed above, refer to
the _Guidelines for breaking the rules_ section below.

## 2. Spacing HTML and CSS

### 2.1 Inline spacing

Inline spacing allows us to add margin around elements flowing horizontally.
This is useful for elements like tabs, tags, breadcrumbs, and more.

Design token names for inline spacing follow this format:
`--fmxe-space-inline-{unit}`

### 2.2 Granular spacing utilities

A set of utility classes can be applied to containers to add margin and padding.

The classes are named using these formats:
1.  `{property}{sides}-{size}` applied to all screen breakpoints
2.  `{breakpoint}:{property}{sides}-{size}` to apply to a specific screen
    breakpoint and up

`{property}` can be one of these values:

| Setting                 | Values                          |
|-------------------------|----------------------------------|
| fmxe-space              | 1, 2, xs, sm, md, lg, xl         |

`{sides}` can be one of these values:

| `{sides}` | Purpose                                                                                   |
|-----------|-------------------------------------------------------------------------------------------|
| `t`       | Set margin-top or padding-top                                                             |
| `b`       | Set margin-bottom or padding-bottom                                                       |
| `s`       | (start) Set margin-left or padding-left in LTR, margin-right or padding-right in RTL     |
| `e`       | (end) Set margin-right or padding-right in LTR, margin-left or padding-left in RTL       |
| `x`       | (x-axis) Set both *-left and *-right                                                      |
| `y`       | (y-axis) Set both *-top and *-bottom                                                      |
| `l`       | (left, deprecated in favor of `s`) Set margin-left or padding-left                        |
| `r`       | (right, deprecated in favor of `e`) Set margin-right or padding-right                     |

`{size}` can be one of the unit values specified above in the _Spacing units_
section. A value of `auto` can also be used for classes to set the margin to
`auto`.

The `{breakpoint}:` prefix is optional and specifies at which screen breakpoint
to start applying the spacing. Classes can be chained together from smallest to
largest breakpoint to override sizes at various screen sizes.

### 2.3 Spacing utility examples

```html
<!-- Set padding on left and right sides to `md` size -->
<div class="px-md"></div>

<!-- Set right margin to `lg` size and left to `md` size -->
<div class="me-lg ms-md"></div>

<!-- Set bottom padding to `sm` size at `md` screen size -->
<div class="md:pb-sm"></div>

<!-- Set bottom margin to `lg` size at smallest screen size, then
     clear it at `md` screen size -->
<div class="mb-lg md:mb-0"></div>

<!-- Set bottom padding to `1px` for smallest breakpoint, `2px` for `md`, and
     the `xs` size for `lg` breakpoint -->
<div class="pb-1 md:pb-2 lg:pb-xs"></div>

<!-- Set right and left margin to auto -->
<div class="mx-auto"></div>
```

## 3. Guidelines for breaking the rules

Because this design system is intended to be used on a marketing website, we
should always strive for flexibility for important styles like spacing.

If the design is not feeling right after exploring the default spacing units,
you should hardcode a desired spacing style relative to one of the standard
sizes.

For example, if you determine that you need padding set to `3.5rem` instead of
the `lg` size's `2rem` value, you should calculate the new value relative to the
nearest standard unit's size using Sass or CSS calculations:

```scss
/* Vanilla CSS */
.pricing-block {
  padding: calc(var(--fmxe-space-lg) * 1.75);
}

// Sass
.pricing-block {
  padding: $fmxe-space-lg * 1.75;
}
```
